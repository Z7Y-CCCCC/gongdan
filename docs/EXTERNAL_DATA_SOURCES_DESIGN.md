# 工单系统外部数据源设计

日期：2026-09-12。状态：原始设计提案（历史基线）。当前实现与开放状态以[一期实施与部署说明](EXTERNAL_DATA_SOURCES.md)为准：HTTP API / SQLite 已接入；MySQL、PostgreSQL、SQL Server 保留适配代码但未完成真实服务/TLS 验收，暂不开放。下文保留原始设计，不是已实现功能清单。

## 1. 设计结论与项目现状

新增「系统配置 > 外部数据源」，作为核心平台的独立能力，与插件中心并列。不要替换工单系统自身的数据库，也不要把外部接入塞进数据库备份页面。

本次检查确认：后端是 Java 8 / Spring Boot 2.7 / JPA，管理端是 Vue 3；已有基于 `AuthenticatedUser.factoryId` 的工厂上下文、系统操作日志和插件后端代理。未找到已有外部数据库连接管理页面。`spring.datasource` 当前用于核心业务数据库，不能拿来动态切换外部源。

采用三层模型：

| 层次 | 回答的问题 | 工单场景举例 |
| --- | --- | --- |
| 数据源 | 连接谁、用什么凭据、是否可达 | ERP 只读数据库、设备采集 HTTP 服务 |
| 数据集 | 读取哪些数据、字段如何解释 | ERP 订单查询、批次温度记录 |
| 业务绑定 | 哪个业务对象使用哪个数据集 | 当前工单号关联外部订单号，工单详情展示温度 |

一期只实现连接管理和数据库元数据浏览。二期实现只读数据集和业务展示。以后需要导入工单时，另建受审核的同步流程，不能让“接通外部数据源”自然获得修改生产数据的权限。

## 2. 页面与交互

入口：系统配置 > 外部数据源。列表使用「全部 / 数据库 / HTTP API」筛选，统一搜索名称、编码，筛选启停及健康状态。

列表列项：名称、类型、脱敏目标、启停状态、最近连接健康、响应耗时、HTTP 状态码、最后检查时间、操作。数据库的 HTTP 状态码显示「不适用」，未检查显示「—」。没有业务数据集时显示「业务数据：未配置」，不能显示“数据正常”。

操作：新增、编辑、测试连接、启用/停用、查看检查记录、归档；数据库额外提供「表与字段」。有引用时禁止直接删除，显示引用数量和位置。停用不删除映射或历史记录。

详情页：

- 连接配置：公共信息与类型专属表单。
- 表与字段：仅数据库，分页显示允许访问的 schema、表、列名、数据类型、可空、主键信息；无权限明确提示，不误报为空库。
- 数据集：二期启用；一期展示说明而非可点击的假功能。
- 检查记录：时间、配置版本、检查阶段、结果、耗时、脱敏错误、追踪编号。
- 使用位置：二期展示工单详情、设备页或看板引用。

表单按钮必须区别：

1. 「测试当前配置」：检查未保存内容，不创建配置、不改变已保存版本的健康状态；短期保留脱敏审计信息。
2. 「保存配置」：只校验格式、权限、网络策略并保存，不要求外部系统在线。
3. 「保存并测试」：先保存，再测试保存后的版本；提示可以是“保存成功，连接测试失败”，不得把保存成功误写成全部成功。

新建默认停用。启用只表示允许受控检查/读取，不表示数据可用。停用时停止自动检查和业务调用，管理员仍可手动测试。编辑类型创建新源，不原地把数据库改成 API。连接、凭据变更后旧健康结果标记过期；二期中关联的数据集需要重新验证。使用乐观锁拒绝覆盖他人的修改。

## 3. 配置字段

公共字段：名称、工厂内唯一编码、类型、用途说明、负责人、启停状态、超时。工厂由登录上下文确定，不能采信浏览器传入的 factoryId。

### 数据库

类型范围：MySQL、PostgreSQL、SQL Server、SQLite。服务端按驱动适配，不提供任意 JDBC URL、驱动类、驱动上传、SQL 控制台或连接属性透传。

网络数据库字段：主机、端口、数据库名、允许的 schema、用户名、密码、TLS 配置、连接/查询超时。SQL Server 一期使用主机和固定端口，不支持自动发现实例。

SQLite 是后端可访问的文件，不是远程数据库服务，也不是用户电脑上的路径。由运维预先登记只读文件标识，界面选择标识；禁止用户输入任意服务器路径、UNC 路径或上传数据库。校验真实路径及符号链接仍在专用挂载目录，使用文件系统只读权限和驱动只读模式；文件不存在不能自动创建。多实例必须确认文件一致性，否则暂不开放该类型。

数据库账号必须由对方授予限定表/视图的只读权限。JDBC readOnly 只是额外保护，不作为只读保证。健康检查执行驱动级验证或固定无副作用探测，再单独检查元数据权限；不会尝试写入来验证权限。业务查询二期仅支持选定表/视图与受控过滤，值参数化、标识符来自验证过的元数据白名单，不支持任意 SQL、存储过程和脚本。

### HTTP API

字段：接口名称（沿用公共名称）、API 根地址、健康检查路径、GET（固定）、认证方式、认证字段、请求总超时。

认证方式：无认证；API Key（Header 名称 + 密钥）；Bearer Token；Basic（用户名 + 密码）。一期 API Key 仅放 Header，不放查询串，暂不支持 OAuth、自动续签和登录接口换 Token。拒绝非法 Header、换行、Host/Cookie/转发头等保留头及与认证头冲突的配置。

健康路径可为空，为空显示「未配置健康检查」，不自动猜测或访问根地址。健康检查默认使用当前数据源认证，但公开健康接口成功不能证明业务鉴权有效。二期通过受保护的数据接口预览进一步验证。

根地址可以带路径前缀，例如 `https://mes.example.com/api/v1`；本产品规定健康路径 `/health` 拼接为 `https://mes.example.com/api/v1/health`。界面显示最终地址以消除歧义。路径必须是本源内路径，禁止完整 URL、`//host`、路径穿越、片段及编码绕过；一期健康路径不支持查询参数。

建议默认总超时 5 秒，用户可设 1–30 秒；连接阶段上限为总超时与 3 秒的较小值，排队、连接、TLS、读取累计不得突破总截止时间。所有数值均为拟定产品默认值，实施时需测试和压测验证。

## 4. 健康状态必须分层

连接状态使用：未检查、检查中、可达、失败、已过期。停用是独立开关；业务数据状态是独立指标，二期才有未配置、未验证、可用、空数据、映射失败、已过期。

| 结果分类 | 用户提示 | 解释 |
| --- | --- | --- |
| DNS / NETWORK / TLS / TIMEOUT | 地址解析失败 / 网络失败 / 证书错误 / 超时 | 尚未证明认证结果；无 HTTP 响应时状态码为空 |
| HTTP 401 / 403 | 认证或权限失败 | 针对被检查接口，不能据此断言具体是哪段凭据错误 |
| HTTP 3xx | 接口返回重定向 | 一期不自动跟随，也不携带凭据跨地址跳转 |
| HTTP 404 / 429 / 其他 4xx / 5xx | 路径不存在 / 请求受限 / 接口响应失败 | 保存实际状态码，提供不同修复建议 |
| HTTP 2xx | 健康接口可达 | 只说明本次请求成功；不证明业务数据、时效或映射正确 |
| DB_CONNECT / DB_AUTH / DB_METADATA | 数据库连接 / 认证 / 元数据权限问题 | 根据驱动错误类别映射；连接与表读取分开报告 |

200 返回 HTML 或 `{"status":"down"}`，在一期只按 HTTP 状态检查时仍属于“HTTP 可达”，界面明确「未验证业务响应内容」。二期数据集还需 JSON 类型、可选业务成功条件、字段、类型、时效验证；不把 204 或空数组直接当映射失败。

记录 `configVersion`、开始/完成时间、耗时、`httpStatus`（可空）、错误分类、traceId、触发者。迟到的旧版本测试不能覆盖新版本；同一配置的并发检查也按执行序号防止旧结果覆盖新结果。一期仅手动检查，默认 15 分钟后标为过期，保留实际检查时间，不将历史绿色状态伪装为实时监控。

二期按源选择自动检查，默认 5 分钟且加抖动；连续失败阈值、恢复通知、429 退避和多实例分布式租约一起实现。未做调度前页面不能宣传“持续监控”。

## 5. 工单业务如何接入（二期）

优先试点：工单详情中的「外部生产数据」只读区。对方设备采集 API 的数据通过工厂内外部编号绑定当前工单，显示批次、温度、采样时间；外部故障只影响此区域，工单创建、派工、报工、审核和库存操作照常进行。

数据集配置包括：数据源、表/视图或 API 相对路径、允许参数、分页方式、JSON 记录路径、字段映射、业务成功条件、预览结果、刷新与缓存策略。只允许有限路径语法和声明式类型转换，不执行 JavaScript、SpEL、模板代码或用户脚本。

示例响应：`{"data":{"items":[{"order_no":"ERP-1001","lot_no":"B001","temperature":36.8,"sampled_at":"2026-09-12T08:30:00+08:00"}]}}`。

| 外部字段 | 内部展示字段 | 规则 |
| --- | --- | --- |
| `data.items[].order_no` | externalOrderNo | 字符串；与本工厂的外部编号绑定匹配，不使用内部数字 ID 猜关联 |
| `data.items[].lot_no` | batchNo | 字符串；保留前导零，不自动新建核心批次实体 |
| `data.items[].temperature` | temperature | 十进制数；明确单位 °C；缺失显示未知而非 0 |
| `data.items[].sampled_at` | sampledAt | 带时区时间；明确源时区，存储 UTC、按工厂时区展示 |

工单编码在本系统按工厂唯一，但对方编码不一定相同。因此建立显式外部编号关联；若一个工单对应多个外部订单，应显式建多条绑定，不靠名称模糊匹配。业务请求根据已授权的工单在后端生成参数，不接受用户传入任意其他工单编号来绕过权限。

预览建议最多 20 条且按字段脱敏，正式读取单页最多 500 条、总量和页数有上限；记录最大响应字节数、分页游标、重复游标检测、schema 指纹和映射版本。数组路径不存在与正常空数组必须区分；必填字段缺失不能静默填零。异常原始记录默认不长期存储。

缓存键至少包含工厂、源、配置版本、数据集/映射版本和标准化查询参数；若结果随权限变化还需包含授权范围。缓存有 fetchedAt 与源 sampledAt，陈旧数据标出“上次成功数据”及时间，超过允许时效显示不可用。禁止用外部缓存参与报工或库存事务。

OEE 不在一期推算。二期先约定设备/产线、统计区间、计划时间、理想节拍和良品口径；外部提供的 OEE 必须标注来源与口径，不直接覆盖本系统绩效指标。

ERP 自动导入属于三期：暂存、字段校验、关联匹配、差异预览、授权确认，再通过现有业务服务创建/更新；必须具备幂等键、增量游标、冲突策略、失败重试和完整审计，禁止直接写核心表或默认覆盖人工修改。

## 6. 安全与运行隔离

- 凭据由管理员通过本系统 HTTPS 提交，保存后不回显明文；响应仅返回“已配置”。不写入 localStorage、浏览器草稿、错误上报或导出。编辑通过明确的保留/替换/清除操作处理，掩码不能作为真实密码保存。
- 服务端可恢复加密保存凭据，例如 AES-GCM，保存 keyId、随机 nonce、密文及认证标签，工厂/源标识绑定为附加认证数据；主密钥从部署密钥设施注入，不与密文一起存于业务库或提交仓库。缺失密钥拒绝保存/解密，支持轮换及独立密钥恢复流程。
- 后端代理只接受数据源/数据集标识，不提供通用 URL 转发接口。浏览器永远不带外部凭据直接调用第三方，不转发核心登录 Token、Cookie、工厂内部签名等身份信息。
- 连接配置和“未保存测试”均受运维配置的出口策略约束，工厂管理员不能通过新增源扩大网络权限。按精确主机/端口及获准 IP/CIDR 管理；工业内网仅显式批准所需网段。拒绝回环、链路本地、云元数据地址和未批准的内部管理网络。
- 每次连接验证 DNS 解析结果并将连接绑定至已验证目标，防 DNS 重绑定；同时保留正确 TLS 主机验证。应用校验配合出口防火墙，覆盖 IPv4/IPv6、数据库驱动及编码变体；禁止重定向绕过、系统代理绕过和 URI 内嵌凭据。
- 默认 HTTPS/TLS 并验证证书；私有 CA 由运维管理，不给普通配置页“忽略证书验证”。确需明文内网接入，必须使用受审批的部署级例外，界面持续提示风险。
- 响应不直接代理给浏览器，不渲染第三方 HTML；限制实际读取字节、解压后大小、JSON 深度。健康探测建议 64 KiB，数据集建议 1 MiB，流式超限即终止。错误只返回稳定分类与脱敏摘要。
- 独立有界线程池/连接资源，不复用核心数据库连接池；外部请求不得放在核心写事务中。建议每源最多 2 个并发、全局 16 个并发，队列有界；人工测试按用户/工厂限流，默认不重试。参数需压测确定。
- 每条源、数据集、绑定、检查记录、缓存均按工厂隔离；所有按 ID 查询携带 factoryId，不能只隐藏菜单。初版管理、测试、元数据和预览仅对经过现有权限机制确认的工厂管理员开放，普通用户只读取其业务权限允许的映射结果。
- 配置变更、凭据替换、启停、测试、归档记录 `DATA_SOURCE` 审计；不记录原始凭据、完整敏感请求/响应或驱动连接串，现有请求日志过滤器也必须检查。健康记录建议保留 30 天，操作审计按系统统一策略。

## 7. 后端结构、存储与 API 草案

在现有 Spring Boot 中新增独立 externaldata 模块，不先拆微服务。接口适配器建议分为 `testConnection`、`inspectSchema`（仅数据库）、`previewDataset`（二期）；返回统一结果，HTTP 状态码保留可空。使用显式能力标记控制前端操作。

沿用 `TokenService.requireUser` 获取可信身份，沿用工厂隔离与 `SystemLogService` 审计模式。可借鉴 `PluginProxyController` 的禁重定向、超时和边界处理，但不直接复用其动态路径、多方法代理和插件 HMAC 协议；外部接口不要求对方安装本系统插件。

建议表：

| 表 | 主要字段与约束 | 阶段 |
| --- | --- | --- |
| external_data_sources | id、factory_id、code、name、kind、driver_type、config_json、enabled、version、归档及创建更新信息；唯一(factory_id, code) | 一期 |
| external_data_source_secrets | factory_id、source_id、key_id、nonce、ciphertext、更新时间；与源一对一，查询不对外暴露 | 一期 |
| external_data_source_checks | factory_id、source_id、config_version、执行序号、trigger、status、error_code、http_status、duration_ms、时间、trace_id | 一期 |
| external_data_sets | factory_id、source_id、code、查询定义、映射定义、参数及缓存策略、version | 二期 |
| external_data_bindings | factory_id、dataset_id、本地对象类型与ID、外部键、展示位置、version | 二期 |

配置 JSON 必须按类型用 DTO/schema 严格校验，不是任意键值容器；密钥不能混入 config_json。跨表引用要在服务层与可行的复合约束中保证工厂一致。新 Flyway 迁移编号在实施时按最新仓库确定，不提前占用当前迁移序列。

一期 API（均为拟定路径）：

- `GET/POST /api/external-data-sources`：列表/创建。
- `GET/PUT /api/external-data-sources/{id}`：脱敏详情/带版本更新。
- `POST /api/external-data-sources/test-config`：受相同授权和出口限制的未保存测试；可通过本工厂 sourceId 使用保留的凭据，绝不读取其他工厂密钥。
- `POST /api/external-data-sources/{id}/test`：手动测试并记录当前版本结果。
- `POST /api/external-data-sources/{id}/enable|disable|archive`：生命周期操作（分别为独立路径）。
- `GET /api/external-data-sources/{id}/schema`：受限元数据，可分页或按 schema/table 查询。
- `GET /api/external-data-sources/{id}/checks`：分页检查历史。

保存并测试由前端串联保存和测试，分别呈现结果；检查接口返回结构化探测结果，`httpStatus` 指上游状态而不是管理 API 状态。管理 API 自身的 401/403 仍代表本系统身份/权限错误，版本冲突使用 409。

新增 `ExternalDataSourcePage.vue`，在 `App.vue` 接入菜单、面包屑、搜索、工作区标签及页面渲染，在 `api.ts` 添加类型化调用；不把全部实现继续堆入 App.vue。页面切换工厂时清空预览和表单，防止跨工厂缓存残留。

驱动依赖需实施时核对 Java 8 兼容性、许可证及漏洞，四类驱动分别做真实集成测试，不能仅以 H2 测试宣布全部支持。若某类未通过，界面标为暂不支持并禁止创建，而非保存一个无法执行的配置。

## 8. 与备份的边界

工单系统数据库备份包含新模块的配置记录、加密凭据和必要审计，这不等于备份了对方业务数据。恢复本系统后建议将外部源停用，核对密钥、目标地址和工厂归属后再启用，避免测试环境误连生产。

HTTP API 不出现在数据库备份目标列表；如将来保存 API 数据快照，命名为“数据归档/快照”，不声称可恢复对方系统。只读数据库源也不自动成为备份目标，外部数据库备份由独立的运维授权、凭据、范围与恢复验证流程负责。

## 9. 分期与验收

一期交付完整连接闭环：统一页面、两大类型、四类数据库适配、四种 API 认证、保存/测试/启停/归档、表字段浏览、检查历史、凭据加密、工厂隔离、出口控制和限流。不开启业务取数、自动同步、任意 SQL、业务写入或自动健康调度。

二期选一个真实接口做贯通验收：数据集、有限字段映射、编号绑定、工单详情只读卡片、受控缓存与可选自动健康检查。先打通一个业务场景，再推广到看板、设备页和报表。

三期按需求增加同步暂存/审批、增量导入、OAuth、更多认证或采集代理。高频设备原始时序数据应保留在采集平台，工单系统读取必要聚合，不承担时序库角色。

上线前最低验收清单：

1. 配置保存与外部可达性独立；检查失败仍能保存，未保存测试不改生产配置。
2. HTTP 2xx、3xx、401、403、404、429、5xx、DNS、TLS、超时和超大响应分类正确；公开 health 成功不出现“业务认证已验证”。
3. 四种认证请求构造正确，服务端保存后不回显秘密；日志、审计、导出、异常和前端草稿均不泄露。
4. 四类数据库用真实引擎验证连接、表列权限及只读账号；SQLite 不存在文件、越界/链接路径及多实例不一致情况被拒绝。
5. 工厂 A 无法查询、测试、编辑或利用源/数据集/检查 ID 访问工厂 B；普通账号不能通过直接请求绕过管理权限。
6. 验证内网审批策略、回环/元数据阻断、IPv6、DNS 重绑定、重定向及路径/Header 注入防护；未保存测试具有相同限制。
7. 超时和慢响应不会耗尽核心连接/线程；重复点击被限流；停用和版本更新后旧探测不能覆盖新状态。
8. 加密密钥丢失明确失败、轮换可读旧数据、备份恢复流程可演练；不自动恢复对外调用。
9. 二期验证空数组、路径不存在、字段漂移、单位/时区错误、陈旧缓存、重复外部编号及未授权工单查询；外部断网时核心工单流程正常。
