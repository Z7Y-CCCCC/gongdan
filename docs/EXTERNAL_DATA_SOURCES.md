# 外部数据源：一期实现与部署

## 已实现范围

入口：管理端「系统配置 > 外部数据源」，仅当前工厂管理员可管理。原工单数据库、插件中心和备份流程不受此模块替换。

当前开放 HTTP API 和 SQLite。MySQL、PostgreSQL、SQL Server 仅保留适配代码和驱动，未通过真实服务/TLS 验收，暂不对用户开放；不仅界面不可选，后端也拒绝其配置写入、连接检查、元数据浏览和启用。不能通过配置出口白名单、直接调用接口或设置某个环境变量绕过此限制。

- SQLite：运维登记的只读文件、固定连接检查、分页浏览表/视图、字段类型、可空和主键信息。
- HTTP：固定 GET；无认证、API Key Header、Bearer、Basic；独立健康路径、1–30 秒总超时。
- 配置保存、测试当前表单、保存并测试、手动检查、启停、归档/恢复、分页检查记录。
- 初始停用；停用仍允许管理员手动检查；不自动轮询或同步。
- 连接健康与业务数据状态分别展示；历史健康结果 15 分钟过期，页面时钟也会更新过期状态。
- 凭据 AES-256-GCM 加密、密钥环轮换、后端代理、按工厂出口白名单、禁止重定向、响应限额和独立执行资源。
- 所有管理接口强制管理员授权；源、凭据复用、检查记录和表字段均按当前登录工厂校验。
- 配置乐观锁；检查记录绑定配置版本，旧版本/迟到结果不覆盖当前版本健康状态。
- 审计模块为 DATA_SOURCE；检查历史每天清理 30 天前记录，审计沿用全局日志保留策略。

尚未实现：业务数据集、JSON 映射、业务接口参数、工单/设备关联、数据卡片、自动健康调度、OAuth、自动续签、数据同步和外部备份。不要把健康接口可达解释为业务认证/字段/时效已验证。

## 数据库升级

新增 Flyway V22：external_data_sources、external_data_source_checks。源编码按工厂唯一；检查记录的工厂/源组合有复合外键约束。

部署前备份核心数据库。生产配置使用 Flyway 迁移后 Hibernate validate，不要在生产用 ddl-auto=update 代替迁移。V20/V21 专属测试固定 target=21；全量迁移测试覆盖到最新 V22。

一期为减少表间一致性维护，将加密凭据保存在源表独立的 secret_cipher 列，而非设计提案中的独立 secrets 表。密文中包含 keyId、随机 nonce 和 GCM 认证标签；AAD 绑定 factoryId:sourceId。API 显式构造脱敏视图，不返回实体密文字段；config_json 只保存经过白名单复制的非秘密配置。这是有意的实现收敛。

没有执行过生产升级、发布、提交或推送。已有配置未被修改，也没有添加任何真实外部数据源。

## 部署变量

所有变量默认留空；核心系统能在没有外部数据源配置时启动。配置了格式错误的密钥环会拒绝启动，防止误用不可靠密钥。出口授权有效但未配置密钥时，匿名 HTTP 可保存，有密码或 Token 的源会明确拒绝保存；SQLite 仍需有效的工厂文件登记。

| 变量 | 格式与用途 |
| --- | --- |
| APP_EXTERNAL_DATA_KEYS | keyId:Base64密钥，多个以逗号分隔；每个解码后必须恰好 32 字节 |
| APP_EXTERNAL_DATA_ACTIVE_KEY | 新写入使用的 keyId，必须存在于密钥环 |
| APP_EXTERNAL_DATA_ALLOWED_TARGETS | factoryId@host:port，多个逗号分隔，精确匹配，无通配符 |
| APP_EXTERNAL_DATA_ALLOWED_ADDRESSES | factoryId@解析后的IP，多个逗号分隔；域名解析的每个地址均需获准 |
| APP_EXTERNAL_DATA_PLAINTEXT_TARGETS | 对特定 factoryId@host:port 开放明文 HTTP 的额外审批列表；仍需前两项授权；不解锁待验收数据库 |
| APP_EXTERNAL_DATA_SQLITE_ROOT | 后端专用 SQLite 目录的绝对路径，需运维只读挂载/只读 ACL |
| APP_EXTERNAL_DATA_SQLITE_FILES | factoryId@fileId，例如 12@equipment_snapshot；对应专用目录的 equipment_snapshot.db |

这里 factoryId 是数据库内部工厂 ID，不是工厂代码。不要将整机内网、数据库管理面或云控制面加入出口规则。

例如批准工厂 12 的 API（示意地址，需换成实际值）：

```dotenv
APP_EXTERNAL_DATA_ALLOWED_TARGETS=12@mes.example.com:443
APP_EXTERNAL_DATA_ALLOWED_ADDRESSES=12@10.20.0.15
APP_EXTERNAL_DATA_PLAINTEXT_TARGETS=
```

若 DNS 返回多个地址，均应在此工厂地址列表内。运行时再次解析并校验，HTTP 客户端连接固定到已校验地址，保留原域名的 TLS 主机验证。回环、链路本地、多播和未批准地址被拒绝。需要配合部署环境出口防火墙，而不是把应用白名单当作唯一网络边界。应用不使用环境中的任意 HTTP 代理，不跟随响应重定向。

密钥请由组织的秘密管理设施生成和注入，不把真实值写入 Git、开发截图或共享命令输出。Java 8 部署应使用支持 AES-256 的维护版本及加密策略。密钥环例示结构是“v1:秘密值,v2:秘密值”，不是字面值可直接投入使用。

轮换步骤：

1. 添加新 keyId 及新密钥，保留旧密钥，切换 ACTIVE_KEY 后滚动重启。
2. 使用管理员逐个保存现有数据源，使凭据按新密钥重新加密。
3. 运维只检查密文 keyId 前缀，确认没有旧 keyId 记录；不要把密文或明文批量导出。
4. 按密钥保留和备份策略管理旧密钥；旧备份仍可能依赖旧密钥，不能立即销毁。

不要在生产开启 Apache HttpClient wire/header 调试；应用默认关闭这两种日志。异常只返回分类和脱敏消息，配置请求限制为 16 KiB，拒绝未知 JSON 字段。

Compose 已将全部变量仅透传到后端运行环境，不传到前端或镜像构建参数；SQLite 没有默认挂载，使用部署覆盖文件为专用目录增加只读挂载。Windows 启动脚本已有通用 dotenv 导入，新增变量放入配置文件即可；不要更改核心 SPRING_DATASOURCE_* 来连接外部源。

## 数据库适配的开放状态与限制

SQLite 当前开放；下面涉及 MySQL、PostgreSQL、SQL Server 的限制描述的是保留适配的实现边界，不代表已开放或已完成真实环境验收。

- 一期网络数据库只接收固定、规范 IPv4 地址，不接收域名、任意 JDBC URL、动态实例发现、用户驱动、连接属性或 SQL。这样避免不同 JDBC 驱动再次解析域名或解析用户连接串造成越权。数据库 TLS 证书需匹配连接的 IP，并由受信 CA 签发；若现场只能提供域名证书，暂不要关闭验证绕过，后续增加审计过的驱动级 DNS 固定机制。
- PostgreSQL 和 SQL Server 必须填写具体 Schema（常见 public / dbo）；不是任意跨 schema 检索器。
- MySQL 禁止 LOCAL INFILE、URL 本地文件、多个 SQL 语句和自动获取公钥。仅有固定 SELECT 1 与驱动元数据读取。
- 只读权限最终由外部数据库账号的 GRANT 保证；JDBC readOnly/SQL Server applicationIntent 不能替代权限控制。不会尝试 INSERT 来证明“只读”。
- SQL Server 使用直连端点；不支持 Always On 路由/副本重定向。出口防火墙必须同时限制驱动可能访问的目标地址。
- SQLite 仅接受运维登记标识；拒绝缺失文件、路径越界和未登记标识，使用 mode=ro / 只读打开标志 / query_only。不自动创建文件，不接受 UNC 或浏览器上传。专用目录必须由运维控制，防止文件检查和打开之间被非信任用户替换；多实例须提供一致的只读快照。
- 元数据每页最多 100 条，最多请求第 101 页，不读取业务记录。零条元数据提示“可能为空或无可见权限”，不会宣称数据库无表。

当前驱动：PostgreSQL 42.7.13、SQL Server 12.10.2.jre8、SQLite 3.53.4.0；MySQL 使用项目已有依赖。驱动需随项目正常漏洞扫描和更新，不自动下载用户指定版本。

## HTTP 行为

根地址 https://mes.example.com/api/v1 与健康路径 /health 拼接成 https://mes.example.com/api/v1/health，界面显示最终地址。只允许受限路径字符；不接受 URL 内嵌凭据、查询串、百分号编码路径、路径穿越、跨域健康 URL。

健康路径留空会显示未配置，不访问根地址；2xx 只标记可达。200 的 HTML 或业务 status=down 不会被误称为业务正常；一期未实现响应体成功条件。3xx 不跟随；401/403、404、429、其他非成功响应分别报告。JSON 映射和受保护业务接口预览属于下一期。

健康响应上限 64 KiB；一期不接受压缩响应。连接阶段最多 3 秒，总超时 1–30 秒。固定有界 16 个外部 I/O 工作者，不复用核心数据库池，不把网络 I/O 放入本地数据库写事务。并发限额及两秒人工检查间隔为单实例保护；目前使用有界分桶限制，可能对碰撞工厂产生短暂共同限流。多实例容量按实例数叠加，网关应另设工厂/管理员限流；尚未声称存在分布式调度或限流。

## 使用与恢复

1. 运维为 HTTP 配置所需加密密钥和按工厂出口规则；SQLite 需配置专用只读目录和工厂文件登记，重启后端。
2. 管理员新增源，选择类型与认证，保存为停用。
3. 测试连接并查看明确的失败分类；数据库单独检查表和字段。
4. 根据需要启用；启用不会触发业务读取或自动健康检查。
5. 健康记录仅代表检查时刻。没有数据集时，工单详情不会出现凭空生成的温度/OEE。
6. 归档保留配置，可从已归档列表恢复为停用。源编码不会因归档释放。
7. 恢复核心数据库到新环境后，必须先保持出口名单为空，再由运维将恢复出的源全部停用，核对密钥、工厂和目标后逐项启用已开放并验收通过的类型。当前没有自动识别“数据库刚恢复”并自动停用的机制，不能忽略这个运维步骤。

核心数据库备份包含配置和密文，但不包含对方业务库或 API 内容；密钥单独备份并管理权限。API 不出现在数据库备份列表。本实现不改变现有备份脚本。

## 上线前与网络数据库开放前的真实环境验收

HTTP / SQLite 上线也需在目标部署环境确认出口、密钥与只读目录权限。每类待开放网络数据库使用获授权的独立测试库与只读账号，准备一张表、一张视图、主键和不同字段类型；在验收测试中运行保留的适配器，不修改生产配置绕过关闭保护：

- 验证正确凭据可连接，错误密码、撤销表权限、网络不可达、TLS 不受信或 IP 不匹配时结果正确。
- 验证表、视图、字段和主键可见范围，特别检查 PostgreSQL/SQL Server 的指定 Schema。
- 由对方 DBA 在数据库侧确认账号没有 INSERT/UPDATE/DELETE/DDL/存储过程写权限。
- 验证 SQL Server 不发生副本路由，出站防火墙阻止任何未批准地址。
- 在相同工厂创建两个源，确认身份/编号不串线；另一个工厂无法凭 ID 读取或复用凭据。
- 慢请求、重复点击和外部断网期间，核心派工、报工、审核和库存流程保持可用。
- 在目标 Java 8 运行时及目标 MySQL 核心数据库上进行迁移/启动演练；本机 H2 SQL 测试不能代替该演练。
