## 2. 核心业务与数据一致性

### 2.1 工单及报工

1. **工单编辑错误处理版本号。** 原实现把请求版本写回实体，不能可靠表达“用户基于哪个版本修改”。现在显式比较已提交版本与数据库版本，冲突返回 409；保存后刷新实体，响应携带实际新版本。
2. **无效日期、分类和工序被静默接受。** 日期采用严格解析，拒绝不存在的日期及结束早于开始；工单分类必须属于当前工厂；工序必须有名称、唯一正序号，数量不得为负，历史空工序项安全过滤。兼容既有状态别名，同时拒绝未知状态。
3. **报工没有以服务器数据完整校验状态和权限。** 现在锁定当前工厂的工单，检查工单可报工状态、有效工序，以及提交人和选定报工人的权限。工序名称取自服务器，不能通过客户端传入名称或 URL 参数替换。
4. **暂停/权限修改与提交报工之间存在竞态。** 报工创建在工单行锁内完成状态与工序权限检查，避免检查完成后工单已改变仍写入报工。
5. **重复审批或并发审批造成重复累计/丢失累计。** 对报工记录和关联工单加锁；同一待审记录的审批/驳回只能有一个获胜，不同报工记录并发累计不会互相覆盖。
6. **工序被移除或重排后，审批可能记入错误工序。** 审批同时核对序号与原工序身份；已移除或改变的工序明确拒绝审批，不再自动新建工序或把数量记到另一工序。
7. **报工数量与累计值溢出、上月筛选混入本月。** 合计使用较宽的中间类型并检查累计边界；拒绝负数、数量合计不一致、倒置时间和非法时长。上月查询增加明确结束边界。
8. **图片存储与数据库事务不一致。** 上传成功而数据库记录回滚时执行对应未提交图片清理；图片绑定及待绑定图片清理使用锁，降低重复绑定和并发清理的冲突风险。

主要实现：`WorkOrderService`、`WorkOrderReportService`、`MobileWorkOrderController`、`DateTimeParser`、`ReportPermission`、`WorkOrderStates`。关键回归见 `WorkOrderServiceTest`、`WorkOrderReportServiceTest`、`DateTimeParserTest` 及 [业务事务集成测试](../backend/src/test/java/com/heihu/workorder/service/BusinessIntegrityIntegrationTest.java)。

### 2.2 产品、库存、出入库与统计

1. **编辑产品可能把新库存改回旧表单值，省略库存还可能清零。** 产品增加版本列与请求/响应版本；更新持有产品锁。省略库存时保留既有值，显式改变库存必须提供版本，过期版本拒绝覆盖。
2. **同一出入库单并发删除可能重复还原库存。** 删除先锁定单据，再锁定涉及产品；重复删除不能重复扣回或恢复库存。
3. **多产品单据的锁顺序不稳定，重复产品行可能处理失序。** 所有涉及产品先按 ID 排序加锁，再应用各行。后续行非法时整笔事务回滚，库存不留下部分变动。
4. **库存加法溢出、负库存输入缺少明确拒绝。** 增量计算检查合法范围，超出支持范围返回业务错误，不允许整数回绕成负值。
5. **单号由记录总数推算，删除后重用、并发生成冲突；数据库又把单号限制为全局唯一。** 自动单号改为日期前缀加随机唯一标识，数据库唯一性改为工厂内唯一。V21 迁移同时兼容旧约束名称。
6. **库存变更后其他视图仍使用旧缓存。** 产品和出入库修改统一失效关联的产品、库存明细及入出库单列表/详情缓存。
7. **库存明细大分页参数溢出、历史空时间值触发异常。** 分页下标采用长整数计算；时间筛选明确处理缺失时间。
8. **看板统计溢出、生产周期丢失不足一天部分、停用任务仍入统计。** 聚合改用长整数，周期保留小数天，过滤停用/空任务，统一执行中与终态别名；极端超产百分比不再转换成负值。

关键回归：`ProductServiceTest`、`InboundReceiptServiceTest`、`OutboundReceiptServiceTest`、`InventoryDetailServiceTest`、`HomeDashboardServiceTest`、`InventoryCacheInvalidationTest`、`BusinessIntegrityIntegrationTest`。

## 3. 认证、会话、权限与短信

1. **旧 token 继续沿用登录时的权限快照。** `TokenService` 每次鉴权读取当前用户及工厂；停用、删除、跨厂变化及时拒绝，降权立即影响鉴权结果。发放会话时也重新检查有效状态。
2. **刷新活动时间/浏览器信息可能复活已踢出会话。** 不再把旧会话整行保存回数据库，改成仅更新对应字段且要求会话未撤销、未过期的条件更新；不信任任意客户端伪造的转发地址作为登录元数据。
3. **重置密码、停用账号或工厂不撤销存量会话。** 普通管理员与超级管理员路径均撤销相应会话，避免重新启用后旧 token 恢复有效。
4. **密码校验与签发之间可插入密码重置。** 网页、手机密码登录、工厂选择和微信绑定等相关凭证路径，在凭证读取/验证前取得用户行锁，并通过外层事务持有到签发结束，避免旧密码校验后在重置完成时再签发新 token。
5. **重启重新启用或提升被撤权的种子账号。** 初始化仅创建缺失数据，不再覆盖已有账号的角色、启用状态和姓名，也不擅自恢复已有停用工厂。
6. **用户可引用其他工厂部门，CSV 未知角色被解释为管理员。** 部门必须属于当前工厂，不存在即拒绝；导入角色只接受明确支持的枚举或显示名称，不用默认管理员兜底。
7. **短信验证码可并发重复消费，登录预检后忽略正式消费失败。** 数据库使用原子条件更新，内存替代实现同步消费；预检通过不等于正式消费成功，二次消费失败必须拒绝签发。短信消费不会因后续登录失败而被错误回滚。
8. **登录失败次数并发丢失，过期窗口可能重复插入撞唯一键。** 失败计数使用独立事务、行锁和有限重试；重置过期窗口时复用已有记录，外层登录回滚不抹除失败次数。
9. **同手机号并发发送可能绕过频率限制并调用多次供应商。** 发送锁与持久化顺序已调整，要求先取得手机号/IP 限流保护并确认记录可写后才调用供应商；不自动重试可能已经发出的短信。等待 IP 锁后重新记录实际发送时间，避免排队时间侵蚀冷却期；内存替代实现也使用原子预占。

已通过的针对性证据包括：实时撤权 8 项、用户边界 7 项、超级管理员会话撤销 3 项、会话持久化 2 项；独立 H2 八线程验证码消费仅一次成功、八线程登录失败计数完整保留；凭证竞态相关定向运行 43 项通过，其中新增 8 项独立 H2 回归。发送并发相关最终定向运行 **23 项通过**，其中 `SmsSendConcurrencyIntegrationTest` 为 7 次测试执行；外部发送器为 Mock，未发送真实短信。

2. **手机号登录后使用错误工厂上下文，上传/下载/导出认证处理不一致。** 恢复实际工厂信息；附件、图片、导出统一 API 地址与认证处理。

6. **库存筛选、汇总和 CSV 导出边界错误。** 统一时间范围、包含结束日全天、校验整数数量，修复汇总键碰撞及 CSV 引号/换行转义。
7. **聊天切换联系人串消息，迟到发送清空新草稿；卸载后重新启动轮询。** 校验请求所对应的联系人/会话，保护新草稿；聊天与实时播报在卸载后不再重启轮询。
8. **重复退出/刷新、同源插件 iframe 和表单组件缺失。** 共享 403 状态处理；拒绝与主站同源或非 HTTP(S) 的 iframe，并同步阻断其消息桥；补齐工单表单组件注册和状态别名识别。
9. **报工权限多选只保留首项、专用进度列表上限不透明。** 自动生成任务、手动添加工序/路线及选择器展示都保留全部权限项；首页专用进度接口达到 500 条时显示上限提示，而不把结果当成完整明细。

## 5. 移动端（H5 与微信小程序）

1. **H5 错用微信绑定流程或在授权失败时构造模拟票据。** H5 使用真实工厂/账号/密码登录协议；小程序保留微信授权流程，但不吞掉授权错误或制造有效凭据。
2. **并发 401、旧登录响应和上传错误使会话不一致。** 统一认证失效处理与去重，隔离旧会话响应；上传也经过一致的 401 处理。
3. **草稿可能跨账号恢复或卸载时丢失。** 草稿按工厂/用户身份隔离，卸载前保存并清理待执行任务。旧的无账号范围草稿不自动恢复到其他账号，也没有自动删除。
4. **登录后跳转与退出行为不准确。** 安全解析内部跳转和 tab 导航；退出不再声称完成微信解绑，也不马上触发自动重新登录。H5 密码输入使用遮挡显示。
5. **报工信任 URL 中的工序和人员信息。** 根据服务器权威工单、工序序号及可选报工人接口构建表单，同时处理工序停用、工单状态与人员权限；服务器仍是最终权限边界。
6. **提交、上传并发导致重复写入或漏图，时间/数量输入不可靠。** 提交与上传互斥；校验整数数量、起止时间和时长；分别使用适合 H5 与小程序的日期和图片控件，受保护草稿附件通过认证下载。
7. **记录筛选竞态、状态统计口径不一致、现场事件重复提交或空 JSON 异常。** 补充最新请求隔离、全状态统计、提交锁与空值处理；统一执行中状态、个人/工厂看板口径。

## 6. 独立插件与 MCP 诊断网关

### 6.1 插件

- **路径规范化不一致绕过鉴权。** 两个插件曾使用原始 URI 前缀判断是否鉴权，而 MVC 会规范化路径；增加回归后，两服务均复现无签名访问返回 200。现在采用与路由一致的应用路径判定，修复后拒绝访问。
- **质量插件跨厂读取记录。** 记录保存可信工厂与操作人上下文，列表按工厂过滤；不再全局返回全部记录。
- **签名未覆盖配置与上下文数字缺少范围验证。** HMAC 原文加入准确的配置头值，替换/移除签名后的配置均会被拒绝；ID 必须为有效正整数范围。
- **代理声明支持 PATCH，但底层连接不支持。** 使用支持 PATCH 的 HTTP 客户端，限制连接/读取等待，关闭自动重定向、Cookie 管理和自动重试。
- **请求体在检查限额前已完整缓冲、应用 context-path 失效。** 改为流式限额读取，处理无 Content-Length 的请求；目标路径兼容配置的 context-path。核心认证信息继续与插件上下文分离。

两个独立插件修复前明确复现 3 个失败：两处路径鉴权绕过及质量记录跨厂泄露。修复后质量插件 **6/6**、设备点检插件 **8/8**；代理 **5/5** 通过。

两个插件仍是内存演示服务，重启会丢失演示记录，不能据此视为已实现生产插件数据持久化。签名协议升级说明见各插件 README。

### 6.2 MCP

- Host/Origin 允许列表原本缺少 SDK 实际启用开关，现在明确启用传输层保护。
- 并发过期会话与迟到 401 共用一次后端登录刷新，不再把已经刷新的令牌反复作废。
- 后端重定向不再自动跟随，避免诊断请求或登录信息离开规定边界。
- 在流式读取阶段执行 2 MiB 响应上限；非 JSON 原文不进入诊断输出，避免绕过按字段脱敏；覆盖超时恢复。

`npm test` 的 HTTP 协议 smoke 已通过，覆盖当前 **7 个只读工具**。这不是 7 条独立测试数量；网关依然没有任意 SQL、命令执行或业务写权限。说明见 [MCP README](../ops/mcp/README.md)。

## 7. 配置、迁移与运维部署

1. **缓存类型配置被无条件 Redis bean 覆盖。** Redis 配置现受 `spring.cache.type` 控制，验证 none/simple 不连接 Redis，默认/显式 redis 保持原生产缓存实现。测试 profile 使用本地缓存，测试日志与正式日志分离。
2. **生产保护遗漏默认 profile 和模拟微信覆盖。** 默认 profile 为 prod 时也执行生产检查；生产环境拒绝开启微信模拟登录，日志短信发送器同样受生产 profile 保护。
3. **数据库并发冲突与标准 MVC 错误映射不准确。** 通用乐观锁及悲观锁/锁等待冲突返回 409，不展示内部数据库细节。追加 MockMvc 回归还复现了不支持方法误报 500、请求内容类型不支持误报 400、不可接受响应格式丢失 JSON 错误体；现分别映射 405/415/406，405 保留 `Allow` 头，三者返回安全中文 JSON。正常请求和坏 JSON 原有 200/400 行为保留，没有新增业务路由。
4. **V20/V21 不兼容已有列/旧索引名称，DDL 分两条删除/新增约束留空窗。** 改为 JDBC 元数据驱动的 Java migration；保留产品版本数据，MySQL 每表单条 ALTER 替换单列唯一，H2 先建后删，支持中断后重试。历史 V1–V19 SQL 未改。详见 [V20/V21 数据库升级说明](DATABASE_UPGRADE_V20_V21.md)。

6. **Redis 认证配置在服务、健康检查与后端之间不一致。** 使用同一配置源并正确传入健康检查，不通过宿主机公开 Redis 端口。
7. **Windows PID 过期或复用可能误停其他进程。** 启停/状态流程核验 Java 进程、准确 JAR 路径及进程创建时间；信息不足时拒绝停止，不再仅凭 PID 强制杀整个进程树。
8. **发布目录和 dotenv 处理不安全。** 发布目录禁止覆盖源码、越出指定项目边界或穿过符号链接/junction；统一带引号 dotenv 的解析，修复生产预检中 5 处 `-or` 表达式错误。
9. **CI 漏检脚本/客户端。** Shell 语法检查改为逐脚本执行，新增移动端测试/双端构建、依赖审计和运维保护检查；组合 Compose 配置在不同密码配置场景中断言。
10. **生产 CSP 阻断合法远程插件。** 两个 Dockerfile 在构建阶段校验 `APP_PLUGIN_ALLOWED_FRONTEND_ORIGINS` 并生成 Nginx `frame-src` 明确白名单；Compose 将同一来源配置传给后端和前端构建。白名单不含 `self` 或通配符，按当前请求 Host 排除主站同源，移动页面仍禁止 iframe。10 项配置回归及真实 Chromium 策略测试通过：允许正常不同源插件，阻断未授权/同源页面，移动端全部阻断。更改名单需要重建前端镜像并更新后端，详见 [Docker 部署说明](../deploy/docker/README.md)；没有用策略测试冒充真实 Nginx 启动验收。

## 10. 兼容性变化与升级要求

1. **数据库先确认基线再升级。** V20/V21 现在是 Java migration；旧工作目录中不可同时打包同版本 SQL。默认 baseline 1 不保证接管任意 Hibernate 库，不能盲目设置 baseline 19 跳过缺失迁移。具体顺序、失败处理和验证边界见 [升级说明](DATABASE_UPGRADE_V20_V21.md)。
2. **核心与独立插件同步升级。** HMAC 原文增加配置末行，旧签名将被拒绝。任何另外实现的插件也需同步更新签名协议；不能只更新其中一端。
3. **显式库存调整需版本号。** 修改既有库存值必须先读取最新产品及 `version`；冲突后刷新并重新确认，不自动用旧值重试。省略库存仍保留库存，未变更库存不是显式调整。
4. **工单、报工边界更严格。** 暂停、结束、关闭、取消等不可报工状态被拒绝；工序/报工人停用或无权限也被拒绝。旧客户端不能继续依赖自报工序名称、任意选择人员或无效日期被静默忽略。
5. **工单/产品编辑应保留服务端版本，正确处理 409。** 不应手工覆盖版本或把并发冲突当成网络错误反复提交。
6. **自动出入库编号不再承诺连续计数。** 新格式保留日期前缀并加入随机标识，依赖旧连续编号格式的集成需检查；唯一性范围为工厂内。
7. **登录撤销与种子行为变化。** 密码重置/停用会使既有会话失效；重启不再恢复被人工撤销的权限或覆盖已改姓名。H5 登录不再依赖模拟微信票据。
8. **客户端数据量仍有限制。** 网页全量辅助查询最多 10,000 条/200 页，超限报错；移动端最多加载 5,000 条并标示统计范围。另有 `HomeDashboardService.listWorkOrders` 专用进度接口仍最多返回 500 条，不能把其列表当成无限量明细。超大数据量应改服务端分页/汇总，而不是继续扩大客户端内存读取。
