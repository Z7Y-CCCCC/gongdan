# 管理端与移动端 UI/UX 复查闭环

本轮收尾的是三阶段动效改造后复查确认的问题。此前已可用的界面不为统一样式而重写；回归范围与真机验收分开记录。

| 问题 | 处理结果 |
| --- | --- |
| 现场事件提交后响应丢失 | 按工厂和用户保留未确认草稿；上一次提交还在途时不允许核对或重发。可按本次上报编号匹配最近记录，匹配到已写入记录就不再写。没找到不等于没写入，不能自动重试。 |
| 任务、工单详情等待报工权限 | 明示「确认权限中…」、阻止重复触发；失败在对应操作旁提示，能重试。 |
| 创建、编辑工单及单位 | 保存期间锁住重复提交；失败在原表单显示并保留输入。焦点进入弹窗，`Tab` 不进背景；按 `Esc` 或选择关闭时，未保存改动需确认。工作区标签不能直接关闭含草稿的表单，普通切换保留草稿和在途请求锁。 |
| 库存收发明细与生产报表 | 首次请求失败不显示假空、假零；有上次报表时明确标注；库存不在新筛选下显示旧结果，不让未确认的范围被导出；就地重试。 |
| 高级运营入口 | 侧栏、搜索与页内切换指向具体模块并同步选中；新窗口保留当前模块。 |
| 打印模板与公共键盘操作 | 工单、入库打印模板保存失败时留在编辑器内，不显示虚假成功。补齐时区、通知、用户、插件、外部数据源和高级运营编辑器的键盘入口或焦点处理；标签页支持 `Home` / `End`、`Shift+F10` 和 `Esc`。 |

## 验收覆盖

- 管理端：812 项 Vitest 通过，结构、国际化、插件契约及生产构建通过。用隔离 H2 后端实跑 40 个常用工作区入口，共 58 项检查（含单位真实创建/修改/删除、英文控件、深色、时区、弹窗和新窗口）；这不是逐一执行 40 个工作区所有业务组合。
- 移动端：227 项测试、H5 与微信小程序构建通过。H5 复跑注册路由中的 9 页：账号绑定/登录、移动工作台、工单列表与详情、报工表单与记录、现场事件、任务、看板。专项浏览器检查覆盖真实请求锁、模拟 503、响应丢失和再次进入核对。
- 浏览器脚本：管理端 `frontend/scripts/desktop-form-browser.mjs`、`frontend/scripts/desktop-recovery-browser.mjs`、`frontend/scripts/workspace-followup-browser.mjs`；移动端 `mobile/test/ui-browser-scenario.mjs`、`mobile/test/field-event-task-browser-scenario.mjs`。浏览器写操作和故障注入仅在隔离夹具中运行。
- 未验收：微信真机授权、原生相机/相册、实体打印机、读屏软件和生产环境数据。现场事件的核对保护并不等同于后端跨设备幂等；需要人工确认时界面会提示。
