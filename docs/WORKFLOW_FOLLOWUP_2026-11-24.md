# 用户流程与性能续查（2026-11-24）

## 已修复

| 区域 | 原问题 | 本轮改动 |
| --- | --- | --- |
| 移动端全部工单 | 进入列表会连续下载最多 5,000 条后才显示；本地搜索也找不到上限之外的工单。 | 首屏只取 20 条，滚动或点击再加载；工单编号、产品编码、产品名称及状态在数据库筛选。列表显示服务端总数，失败可重试当前页，迟到响应不会覆盖当前筛选。 |
| 管理端基础资料 | 客户、供应商、仓库列表只取前 500 条。慢查询可能覆盖新筛选，连续点保存可能重复提交。 | 每页 50 条，支持翻页及重试；保持查询条件、忽略过时响应、保存防重。删除最后一页最后一条时退回有效页，同一时间创建的记录按 ID 稳定排序。 |
| 销售订单 | 无效日期可能返回 500，交付早于下单可保存；多行数量合计可能出现整数溢出。 | 返回可纠正的字段错误；拒绝倒置日期；合计用 64 位整数，JSON 仍为数字。 |
| BOM 与销售订单删除 | 请求处理中的确认框未正确锁定，完成后可能仍停留在旧确认框。 | 删除期间锁定确认，成功立即关闭并刷新；失败提示原因、保留原记录。 |

工单搜索以当前工厂为范围，支持历史状态别名；`%` 和 `_` 按字面匹配。旧工单即便没有产品名称，也能按工单号查到。

## 验证

- 后端 51 项定向回归通过，其中 178 个 API 路由冒烟无 5xx；H2 集成测试覆盖字面搜索、工厂隔离、状态别名及同时间分页。
- 管理端全套 Vitest 161 项、移动端全套 81 项通过；管理端生产包、移动 H5 和微信小程序均构建成功。
- 390px H5 浏览器使用隔离夹具：登录后首屏只请求 20/42 条，加载更多后为 40/42，搜索直接命中尚未下载的最后一条，并可用状态筛选切换结果。

## 范围

本轮不新增数据库迁移、不部署、不访问真实业务数据。移动任务和看板仍有基于多页数据的客户端统计，本轮没有修改其口径；真实业务数据量下的性能提升未压测。
