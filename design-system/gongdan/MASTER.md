# 工单系统 UI/UX 覆盖

此文件只约束本项目。上游检索是候选参考，不自动覆盖现有品牌、实现或依赖。

## 基线

- 管理端 Vue 3.5；移动端 Vue 3.4.34 / uni-app。移动端不得直接采用 Vue 3.5+ API；H5 与微信小程序分别验收。
- 保留现有绿色、现有 UiIcon、字体与框架；不新增 GSAP、字体库、UI 框架或营销式大标题。
- 当前 tokens：品牌 `#00b889`；文字动作背景 `#007a60`、悬停 `#006b53`；图标圆角 7px、登录卡 14px、普通弹窗 6px。以工程实际样式为准，不把这些值强加给其它项目。
- 主内容优先：简短页面/分区标题、关键数字、表格与表单；删除装饰性副标题、能力宣传及重复口径说明。权限、错误、截断、必填、不可逆后果仍需可见且紧凑。

## 操作与反馈

- 桌面常用动作目标至少 36×36px；触摸动作至少 44×44px。相邻危险动作留间距，不能只把图画大而命中区很小。
- 通用、明确上下文的搜索/编辑/删除等图标优先，保留准确 `title`、`aria-label` 和键盘焦点。复杂业务用 `ui-action-button`：图标＋2~4字短名，不套固定宽度图标按钮。
- 操作记录、导入日志、行高、打印方式、BOM、审批与批量状态要常显短名；手机底栏常显名称。悬停/长按不是可发现性的替代品。
- 保存、审批、删除的处理中反馈不能消失；同一写请求只发一次。危险确认写具体结果与目标/数量，取消在左、实际动作在右，不只写“确定”。
- 颜色不是唯一信号：状态有文字/图形，链接有可点性提示，必填和错误有可见标记；灰度下仍能分辨。
- 动效只服务反馈和层级。沿用 `--motion-fast/base` 的 140~220ms 项目节奏，遵守 `prefers-reduced-motion`；不把这一时长当所有产品的通用标准，不做持续装饰运动。

## 场景验收

| 场景 | 验收 |
| --- | --- |
| 表格 | 查询条件与页码不串；总数真实；迟到响应不覆盖新条件；截断有短提示；导出说明实际范围；同类动作一致。 |
| 表单 | label 输入后仍可见；错误指出字段与修正路径；失败保留输入；关闭/返回不默默丢修改；小数、日期与边界不隐式舍入。 |
| 手机 | 无悬停也能辨认关键动作；底栏不盖内容；不同缓存页只有当前导航；详情/报工 query 不串；返回恢复当前筛选与位置。 |
| 错误/慢请求 | 处理中有真实反馈；失败可重试；保留原数据与草稿；无假进度、空白页或重复写入。 |
| 危险/权限 | 明确权限不足与不可逆后果；批量部分失败显示实际成功数，失败目标可重试；确认/取消位置稳定。 |

本地自动测试与浏览器验收分开记录。未测的微信真机、辅助技术、生产数据量与第三方服务，不宣称已通过。
